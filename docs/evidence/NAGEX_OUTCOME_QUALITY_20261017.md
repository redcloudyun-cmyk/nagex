## 4. C2 — presentations

### 4.1 Engine decision (ADR-0020)

The text-only writer could not make charts, pictures or tables, and a hand-written chart part (XML plus an embedded workbook for editability) is exactly the engine the directive says not to build. **PptxGenJS 4.0.1** (MIT; published 2025-06-26 - not a fresh release) writes the file; NAgex keeps the structure (what a slide may contain), the font sizes, and the checks. Vetting:

| Question | Answer |
|---|---|
| Install | `npm install pptxgenjs@4.0.1 --save-exact --ignore-scripts` (no lifecycle script ran) |
| Dependencies | `jszip`, `image-size`, `@types/node`, and **`https@1.0.0`** - read: a package of one `package.json`, no code, no install script (npm shows "https mediation"); Node's own `https` always wins over it |
| `npm audit` | reports `image-size` (JXL / HEIF / ICNS parsers, denial of service) through pptxgenjs. **The installed build never imports `image-size`** (searched: no shipped file references it), and NAgex passes only PNG / JPEG that it recognised from the bytes itself. The pre-existing `js-yaml` moderate finding is unrelated. Not fixed here; disclosed |
| Package conformance | the library lists content types for slide masters it does not write (`slideMaster2/3.xml`) - tolerated by PowerPoint, not conformant: the dangling entries (and nothing else) are removed after writing |
| Old writer | `buildPptx` stays as a deterministic fixture builder for older tests; it is **not** on the production path (`LocalPptxPresentationAdapter` now uses the rich writer) |

### 4.2 What reading the real PowerPoint renders found (each fixed, each pinned by a test)

| # | Defect | Fix |
|---|---|---|
| 1 | The **font size NAgex chose was ignored** for title / body placeholders (a 19 pt choice came out as the master's 24 pt; 424 pt of text in a 349 pt box) | the size is set on **every run** |
| 2 | Pie labels read "0% / 1% / 0%" instead of 55 / 25 / 20 % | a percentage label formats a *fraction*: `0%` |
| 3 | A one-series bar chart had a different colour per bar | one colour per series (per category only for a pie) |
| 4 | The unit as an axis title rendered as a stray rotated glyph | the unit travels in the number format (`45분`, `73%`, `12,000원`) |
| 5 | Titles centred | left |
| 6 | A long table reserved the takeaway space on **every** page of the split | only on the last |
| 7 | **A bar chart on PowerPoint's automatic axis started at 66 %** - 73 % against 72 % looked like a big gap, 83 % three times taller (found in the real DECK-1) | bars always start at zero (or the lowest negative); **the evaluator fails a bar chart that does not** |
| 8 | "30,000$" | a currency symbol stands in front of the amount |
| 9 | Three takeaways overflowed the fixed strip under a table (found in the real run 2) | the takeaways take the space actually free under the table, reserved when the table is planned; smallest readable size 12 pt |
| 10 | A 7-row table split in two for no reason | one row-height floor and the same 12 pt minimum everywhere |

### 4.3 What stays NAgex's, and how it is enforced

- **The figures are the person's.** Every number a chart / table cell / key-figure card states must appear, as the same number, in the request, the instructions, the source documents or the remembered context - otherwise the slide is shown as its takeaways and the person is told in their language ("2번 슬라이드의 차트: 수치가 요청이나 자료에 없어 글로 바꿨어요."). A number the model *computed* (a total, an average) is not the person's.
- **Pictures arrive by reference.** The model is offered `image_1 = "<title>"` for the person's own PNG / JPEG artifacts (owner-checked); it never sees a store id or a URL; a reference it was not offered is not drawn; a picture is known to it only by its title.
- **A slide that only says information is missing never reaches the file** ("작성을 유보합니다" + "확보되는 대로 보완될 예정입니다"): left out, recorded, the person told. (This was a real defect of run 1: two such slides in DECK-1.)
- **The exact number of slides asked for is kept**; the sources of a deck go to the cover's speaker notes (a closing slide only when asked for).
- A plain deck keeps exactly its old result keys; `visuals`, `demotions` and `notices` appear only when there is something to say.

## 6. Quality-driven recovery (bounded)

| Where | What | Bound |
|---|---|---|
| Prompts | write every requested section qualitatively; a missing table value is "미정" / "not set"; no invented To / From / Date; a picture does not replace the text | -- |
| Document draft that still says content is missing | asked **once more**, naming exactly what remains; the draft with fewer marks is kept; the result's `review` says what was found and what remained | one extra call, never a third; a failing retry keeps the first draft. **Not exercised live** (no run-3 first draft needed it) - unit-tested with a stand-in router (6 tests) |
| Deck slide that says nothing | left out and recorded | deterministic |
| A figure that is not the person's | the slide becomes text | deterministic |

No model was asked "is this good?": there is no self-scoring loop.

## 7. C3 — images

- **Generation: BLOCKED_WITH_EVIDENCE.** The real Google image adapter answered `RESOURCE_EXHAUSTED` (quota) when last called (`docs/evidence/product-builder-20261017/live/live-result.json`); OpenAI, NVIDIA NIM and a local GPU have no credentials here. A further probe would have to be authorised: a *success* may be billable. **No image-provider output exists in this evidence.**
- **Evaluation tooling (certified without a provider):** `src/creation/quality/media-quality.ts` + `scripts/image-quality-check.mjs` (decodes the picture in Chromium): PNG / JPEG from the bytes (an HTML error body saved as `.png` fails), size, aspect ratio, **blank / flat fails** (pixel facts), requested text read back by a named **advisory** reader, and the EDIT scenario (differs from its original, keeps its shape) kept apart from CREATE. 11 tests. `image-check/`: the real chart picture **PASS**; a flat grey fill **FAIL `NOT_BLANK_OR_FLAT`** (negative control).
- **Prompt fidelity** (does the picture match the prompt?) is **not decidable from pixels**: human review or a vision model named advisory. Not run.
- **Save and reuse: PASS.** A stored image is embedded into a document (`![alt](canonical address)`, resolved through the owner-checked store at download) and into a deck (by reference); another person's, another tenant's, an unknown or malformed address each show the same "unavailable" line (document) or are not drawn (deck). End to end in DOC-3 and DECK-2 (the picture is a bar chart rendered locally from the person's data - **not an AI-generated image**, and reported so).

## 8. C4 — video

Certified on an MP4 assembled box by box (11 tests): **the parser is certified; no real clip was evaluated.** Higgsfield / Veo generation remains BLOCKED (no key pair, no billing, no authorised spend) - `docs/evidence/NAGEX_VIDEO_GENERATION_20261016.md`.

## 10. Limits and what was not done

- **One reviewer, the builder.** Human review above is the assistant's. Three live runs of five files each is a small sample; the model varies run to run (run 2 was worse than run 3 on DOC-2 / DOC-3 for reasons the prompts did not control). **No QUALITY_PASS in the "a person would like it" sense is claimed.**
- Measured in **Microsoft Word / PowerPoint 16 on Windows only** (`scripts/office-render.ps1`, local certification, not part of CI). Not opened in LibreOffice, Keynote, Google Slides or Office for the web / older Office.
- The Office harness hid two Word hangs while it was built (a `SaveAs2` on a read-only document waited on a hidden prompt; the instance was closed gracefully through COM - one process kill was refused by the permission layer and not worked around). The edit round trip now works on a plain file copy.
- Fonts are those of this PC (Malgun Gothic for Korean, Calibri for English); the text-fit is an **estimate from character widths** checked against PowerPoint's `BoundHeight`, not a font-metrics layout.
- The version comparison (`diffDecks`) compares titles and bullets only: a changed chart value or table cell is not shown in a diff. A revision of a rich deck reaches the model as the Markdown summary of the old deck.
- The Main UI has no control yet to attach a picture to a document or a deck: today it is the API (`sourceArtifactIds`).
- A SUPPORTED figure may still sit on the wrong thing; only a person or an independent reader can tell. The label typo class ("정 조율") is not detected.
- The chart-data check is exact only when the expected data is declared; the live decks did not declare it (NOT_RUN).
- C3 / C4 real-provider runs and C5 are not done (above).
