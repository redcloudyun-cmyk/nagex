## 2. What the person experiences (real Chromium, production server)

Pictures of the card at each decision: `docs/evidence/product-builder-20261017/cards/`. The stand-in "mockups" there are a plain wireframe drawn by the test (not generated by an image model); the preview/test pictures are of the stand-in site.

1. **Plan gate** - the plan, what it does not include, what NAgex assumed, and what approving sets going ("asks google for 3 visual mockups"). Nothing has been requested, written or deployed (asserted: the model/image counters are unchanged).
2. **Design gate** - three pictures and the design spec. Still no code.
3. **Build gate** - engine, framework, data, hosting, steps, the checks it must pass, what approving allows and forbids, versions frozen. Still no code (engine counter 0).
4. **Built and tested** - nine checks pass in an isolated browser, one picture per width (1280 / 768 / 390), a sandboxed preview. Nothing is online.
5. **Deploy gate** - the target in the clear; nothing sent.
6. **Online** - appears only after the address was opened and checked ("Checked just now: the address answers (HTTP 200) ...").
7. Korean and a 390 px phone: texts in Korean, no sideways scrolling, no raw keys or technical codes.

Negative and edge scenarios (all in `tests/product_builder_browser.test.ts` and `tests/product_builder_workflow.test.ts`): a change request makes version 2 with a new approval and the first approval is dead; declining changes nothing; image quota blocks with the provider's reason and continues when the quota is back; a failing product is sent back with what failed and the repaired one passes; a stranger gets 404 for every project route (including `preview-link`, which first leaked a 409 and was fixed); the preview link cannot be forged or walked out of; anonymous callers get 401.

## 3. Truthfulness and approval properties proven (workflow tests, scripted stand-ins)

Nothing runs before its gate; approvals bound to version and hash and consumed once; a changed artifact withdraws what depended on it; a stored artifact that no longer matches its approval is refused; BLOCKED with typed reasons for quota / no provider / unconfigured / empty / no engine / unavailable engine / no test runner / no hosting; a repair loop that ends in FAILED (never previewed or deployed); unsafe generated files (no `index.html`, `../`, oversized) fail the project; the address must answer with THIS build (a parked page, wrong build, smoke failure, or no verifier is not "deployed"); an uncertain deployment is never retried, also across a restart; a model that is down blocks (not fails) the step and a failed change request changes nothing; mockups made before a design failure are not made twice; an approval granted in the approvals inbox is carried on; at most five unfinished products per person.

## 4. Live check (opt-in `tests/product_builder_live.test.ts`; real model, real isolated browser)

Environment: `GEMINI_API_KEY` of the development machine, `NAGEX_GEMINI_MODEL=gemini-flash-lite-latest`, free-tier text quota. Synthetic request only. **Nothing deployed.** The approvals were given by the test playing the person (automation, through the same Approval Authority).

- **Plan, design, build plan:** produced by the real model and accepted by the closed-shape validators (a plan with pages Dashboard and Customer Records, non-goals including "Backend server deployment or cloud database storage" and "User authentication").
- **Mockups:** the real Google image adapter answered `IMAGE_QUOTA_EXCEEDED`; the project was BLOCKED with that reason and offered no pictures. To exercise the downstream steps the test then chose a labelled stand-in provider (`stand-in-images-NOT-REAL`). No real picture exists.
- **Run 1** (before the improvements below): the model wrote a multi-view application whose own checks named the customer list and search field, which were hidden behind a tab on first load. Three builds failed those checks and the project ended **FAILED** (truthfully; never previewed). The tester's failure detail was too vague to guide a repair and the prompts did not say that checks run on the first screen.
- **Improvements:** the tester now says why (absent from the page vs present but hidden on first load; for a search, what stayed visible); the build-plan and engine prompts say that checks look at the page as first loaded. The Gateway gained a per-request time budget and an output-token ceiling (a 10k-token site outlasted Gemini's 30 s default and its default output limit).
- **Run 2:** PASS in 96 s, zero repairs: all of `builtin.loads`, `no-sideways-scroll` at 1280/768/390, five plan checks (including search narrowing `Alice Smith` and hiding `Bob Jones`), `no-console-errors`, `no-external-requests`. Pictures: `docs/evidence/product-builder-20261017/live/screenshots/` (1280 and 390 px); generated files: `.../live/site/`; machine-readable result: `.../live/live-result.json`. The generated site is model output kept as evidence; it is not part of NAgex.

## 6. Not done / disclosed

- **No real deployment** to any hosting provider (no credential). The Vercel adapter follows the documentation fetched 2026-10-17 (`POST /v13/deployments` with inline base64 files and `target: production`; `GET /v13/deployments/{id}` for `readyState`); whether `projectSettings` with all-null values is accepted for a first deployment is **unverified** and the first real run may need a documented adjustment. Cloudflare Pages direct upload is **not implemented**: the file-hash/upload protocol is not in the API reference page that was read, and an interface is not invented.
- **No real mockup pictures** (development key has no image quota; no other authorized provider).
- **No agentic coding engine and no container sandbox.** Only static, self-contained sites can be built. A project that needs install/build/server code cannot be built and would end BLOCKED (`SANDBOX`). The `CodingEnginePort` is ready for an engine that runs inside a sandbox.
- The deployment's cost is the hosting plan's; NAgex states that it does not control it and enforces no spending cap. Model cost is the configured provider's (free tier in the live check).
- The preview does not persist what the person types (opaque origin, no storage); the card says so.
- Preview links live in process memory (a restart invalidates them).
- Only the most recent unfinished project is restored on refresh.
- A stranger who obtains a signed preview link can open that preview for 30 minutes (the link is the credential; it is not logged).
- Electron shell, Android and the other missions' blocked items are reported in their own documents.
